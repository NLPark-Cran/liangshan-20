# 群核科技（Manycore Tech）赛事与接口调研

调研时间：2026-11-15
调研人：陈知远（Ken）
用途：评估「浙江生态文明二十年」2D 手绘地图叙事项目能否参赛 / 接入群核技术

---

## 核心结论

1. **有一场正在报名与提交的赛事**：群核科技 Aholo 全球 3D AI 黑客松，2026-10-19 开放报名，**11-19 19:00（北京时间）作品提交截止**。今天 11-15，还剩 3 天半，且截止前可多次提交、以最后一次为准。
2. **赛题不限定 3D 方向，但工具是硬门槛**：据公开报道与赛事配套课程材料，赛题未限定具体方向，游戏、网页、影视、3D 打印、具身智能、空间设计都在可探索范围。唯一强制项是必须使用 3D 生成模型 Aholo Lux3D，并让它在作品核心 3D 内容或关键创作流程中起作用。评审第一条「群核技术栈应用」权重最高（赛事页标注 30%，该页为 JS 渲染、归档无正文，具体权重待确认）。
3. **2D 手绘地图可以接，但只能接一个点，不能接成一套**：真实可行的做法是在地图上挑 1 到 2 个点位，用 SpatialGen（单图/图文生成 3D 世界）或 Lux3D（图生 3D 资产）做出可进入的 3D 场景或可旋转的实物，作为地图的「传送点」。把整幅地图改造成 3D 沙盘，3 天做不完，也不符合赛题原意。
4. **酷家乐的「未来创造+」校园设计大赛走不通**：这是必须用酷家乐出空间效果图的学生个人赛（户型 ≥70㎡、每空间 ≥2 张渲染图 + 3D 全屋漫游），2D 手绘地图没有对应赛道。且 2026 年第九届是否启动，官网查不到，未能核实。

### 1.4 技术战略关键词

- **空间智能（Spatial Intelligence）**：公司自我定位的核心词，官网、财报、招股书统一使用。
- **「工具—数据—模型」飞轮**：空间编辑工具层 → 空间数据层 → 空间大模型层，三者闭环。官网原文：「已形成『空间编辑工具-空间数据-空间大模型』的业务飞轮」。
- **开源路线**：InteriorNet 室内数据集开源；2025-03 在英伟达 GTC 2025 开源空间理解模型 **SpatialLM**（[经济观察报](http://m.eeo.com.cn/2025/0320/717462.shtml)），登上 Hugging Face 趋势榜前三；2025-08-25 首届技术开放日发布并开源空间生成模型 **SpatialGen** 与 **SpatialLM 1.5**（[大河财立方](https://www.dahecube.com/article.html?artid=245296)）。
- **战略升级**：2025 年 12 月「酷+大会」宣布从软件服务商转型为「空间智能基础设施提供商」（[ivendor](https://www.ivendor.com.tw/website/digital_column_detailed/5755)）。
- **AIGC 设计**：2023 年发布「酷家乐 AI」，为 3D 云设计赛道首个自研 AI 模型的 AIGC 产品（[冶金工业规划研究院转载研报 PDF](http://mr.minmetals.com.cn/hyyj/qydt/202512/P020251204406690275065.pdf)）。

- 提供算力与积分支持：报名成功领首笔积分，完成组队并提交选题后解锁更多积分；在魔搭社区发布作品经核验可额外获 20 小时 Notebook GPU 额度。

## 三、技术接口评估

### 3.1 对外开放的 API / SDK

Aholo 空间智能开放平台，网关 `https://api.aholo.cn`（海外 `https://api.aholo.ai`）。

| 服务 | 能力 | 关键接口 |
|------|------|---------|
| Asset | 文件上传凭证、分块上传 | `GET /asset/v1/token`、OUS 上传系列 |
| World | 3DGS 世界重建、SpatialGen 世界生成、列表与详情 | `POST /world/v1/reconstructions`、`POST /world/v1/generations` |
| Lux3D | 多模态生图、图生 3D、文生 3D、材质迁移、多格式导出、部件拆分、关节化、数字人绑骨与动画重定向 | `/lux3d/v1/generate/img-to-3d/task/create`、`/lux3d/v1/generate/text-to-3d/task/create`、`/lux3d/v1/multi-format-export/task/create` |
| RenderCloud | 离线渲染、实时流、Mesh 上传解析 | `/rendercloud/v1/jobs`、`/rendercloud/v1/streams` |
| SpatialUnderstanding | 空间理解，点云场景解析 | `POST /spatial-understanding/v1/tasks` |
| Reality | 手机拍摄/图片/全景重建（web-scan 系列） | `/web-scan/v2/reconstructions` |

来源：[AHOLO Open API 参考](https://labs.aholo3d.cn/api-docs/api-reference)、[llms.txt 全量接口索引](https://labs.aholo3d.cn/api-docs/llms.txt)。

**SDK**：
- TypeScript：`npm install @manycore/aholo-sdk-asset | @manycore/aholo-sdk-world | @manycore/aholo-sdk-lux3d`
- Java：`com.manycoreapis:aholo-sdk-*`（Maven Central）
- Python：`pip install manycore-aholo-sdk-*`
- 源码：https://github.com/manycoretech/aholo-spatial-sdk
- 鉴权：请求头 `Authorization: <API key>`，无需 Bearer 前缀；环境变量 `AHOLO_API_KEY`

**Aholo Viewer（3DGS 前端渲染器）**：
- npm 包 `@manycore/aholo-viewer`，支持 WebGL2/WebGPU，支持 SOG/3DGS 流式加载、`AbortSignal` 取消、按需回读 CPU 数据。
- 开源仓库 https://github.com/manycoretech/aholo-viewer（C++ 核心，约 1.1k star）。
- 文档：https://aholojs.dev/zh-CN/manual/getting-started/
- 另有嵌入代码方式：在 Reality 项目页点「获取嵌入代码」，粘进网页即可。

**其他开源**：ComfyUI 插件（Aholo World Generate）、KooRender 3ds Max 插件、`@manycore/aholo-splat-transform` 测试套件、SpatialLM / SpatialGen 模型仓库。

### 3.2 能力边界：能不能做「乡村/园区 3D 场景」和「2D 地图转 3D」

| 需求 | 是否支持 | 说明 |
|------|---------|------|
| 单图或图文生成一个 3D 空间/世界 | **支持** | SpatialGen「世界生成」输入支持纯文案、单图或图文，至多 1 张图片。输出 3DGS 或 mesh |
| 生成单个 3D 物体（村口牌坊、观鸟屋、农具） | **支持** | Lux3D 图生 3D / 文生 3D，输出 GLB/PLY/OBJ/STL 等；面数 10,000 至 300,000；必须指定版本 G1 或 G1-Turbo |
| 真实地点重建（把一个村口/湿地扫描成 3DGS） | **支持，但需实拍** | World 重建需要 ≥20 张图片，或一段视频，或 Insta360 的 insv 素材。没有实拍素材就做不了 |
| 从 2D 平面图/手绘地图直接生成 3D 地形或城市模型 | **不支持** | 接口里没有「平面图→三维地形」这一路。SpatialUnderstanding 做的是点云场景解析（1000 积分/次），输入是三维点云，不是平面图 |
| 把现有 2D Canvas 地图嵌入 3D 场景 | 不适用 | 群核工具不提供「2D 图层贴到 3D 场景」的能力，这一步得自己用 three.js 做 |
| 视频生成（保持时空一致） | 支持 | LuxReal，可用于做演示视频或片头 |

## 四、判断依据：2D 手绘地图能怎么接

### 4.1 三个真实切入点（按可行性排序）

**切入点 A：地图作导航，点位作 3D 传送门（最推荐）**

在现有手绘地图上挑 1 个点位（余村、青山湖、下姜村任选其一），把该点位的画稿或一张实景图作为输入交给 SpatialGen，生成一个可进入的 3D 世界；点击地图上的节点，弹出 Aholo Viewer 嵌入的 3D 场景，可以拖着看、走一圈，看够了回到手绘地图。

- 用到的群核能力：SpatialGen 世界生成 + Aholo Viewer 嵌入。
- 工作量：生成 1 个世界（10 积分，免费额度 30 次够用），拿嵌入代码，写一个弹层组件。**1 个工作日以内。**
- 叙事上的说法要准：这是「意象重建」，不是地理还原。报告书里写清输入是什么、生成结果和真实的差距在哪里，比含糊带过更得分。
- 风险：SpatialGen 生成的世界是风格化空间，识别不出「这是余村」。所以要靠地图点位标签和文字说明把它锚回现实。

**切入点 B：手绘符号变可旋转实物（最稳）**

地图上的视觉符号（共享菜园的木牌、观鸟屋、水车、稻垛）本身是 2D 画出来的。用 Lux3D 图生 3D 把它们做成可旋转的 3D 资产，放在「图鉴」或「点位详情」里，鼠标拖动看背面。等于给手绘元素加了一个维度。

- 用到的群核能力：Lux3D 图生 3D，导出 GLB，three.js / `<model-viewer>` 加载。
- 工作量：1 到 2 个资产，每个生成约 4 到 5 分钟（官方课程实测），加调试。**半个到 1 个工作日。**
- 优势：Lux3D 是赛题强制项，这条路把强制项做扎实了。评审 30% 那一栏能拿到分。
- 风险：手绘水墨风的图生 3D 效果不一定好，细线条和留白容易被做成厚块。需要试 2 到 3 次，挑一个能用的。

**切入点 C：实拍重建一个真实点位（最贵）**

用 3DGS 把校园一角或村里某处扫成真实场景，作为地图上的「真实锚点」。

- 用到的群核能力：Aholo Reality（手机拍视频上传重建）。
- 工作量：现场拍摄 5 到 10 分钟 + 上传重建（20 积分，免费 20 次）+ 嵌入。**拍摄加返工至少 1 天，且要看天。**
- 判断：如果小组里有人今天就在余村或临安，可以做。否则放弃，别硬排。

**组合方案（3 天半内可交付）**：A 做 1 个点位 + B 做 1 到 2 个器物，加起来 1.5 到 2 个工作日，剩半天写报告书、录 Demo、发小红书。这是窗口内唯一现实的做法。

### 4.2 硬蹭的红线

以下说法或做法，评委会在 30% 那一栏直接扣分：

1. 把手绘地图整体重做成 3D 沙盘，声称「用群核做了空间可视化」。实际上没调群核任何一个接口，只是自己写 three.js。
2. 地图上贴了几张 Lux3D 生成的图，但生成物是装饰，不参与交互，也不承载叙事。
3. 用群核生成的东西和作品主线无关，纯粹为了凑「用了群核工具」。
4. 在报告书里夸大 SpatialGen 的能力，说它能「还原余村的真实地形」。它不是地图测绘工具。

判断标准很简单：把群核那部分拿掉，作品还完整吗？如果完整，说明是硬蹭。

### 4.3 2D 项目是否处于劣势

- 赛题层面：不劣势。「不限方向、不给命题」是官方原话，网页开发被明确列为可探索方向，还专门设了「怪点子奖」「最没有用奖」给非主流创意留口子。官网展示的示例里就有「云水禅墟网页制作」「古村探险小游戏」这类重叙事、轻建模的作品。
- 评审层面：有结构性劣势。30% 权重压在「群核技术栈承担核心作用」上，纯 2D Canvas 项目在这一栏接近 0 分。即使有趣程度（25%）、创新性（20%）、完成度（20%）都拿满，上限也只有 70% 左右。
- 结论：接到 3D 资产上去，2D 不是短板，反而是差异化的叙事底盘；不接，就是陪跑。

### 4.4 时间可行性

今天是 2026-11-15（周日）22:24，截止 2026-11-19 19:00，实际可用约 3 天半（11-16 至 11-19 白天）。

| 事项 | 预估 |
|------|------|
| 注册账号、报名组队、领积分 | 0.5 小时 |
| Lux3D 试生成 1 到 2 个器物（含返工） | 0.5 到 1 天 |
| SpatialGen 生成 1 个世界并嵌入 | 0.5 天 |
| 前端集成（弹层、加载态、移动端适配） | 0.5 到 1 天 |
| 报告书 + Demo 录屏 + 小红书发布 | 0.5 天 |
| **合计** | **2 到 3 天** |

排得开，但没有余量做第 4 个资产，也没余量重做地图架构。
